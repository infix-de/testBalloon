## 🎈 TestBalloon 1.0.0

_Kotlin testing made easy, everywhere._

We are thrilled to announce **TestBalloon 1.0.0** — the first stable release of TestBalloon, a Kotlin Multiplatform test framework designed to make testing a joy across JVM, Android, JS, Wasm, and Apple targets.

This milestone marks the culmination of everything learned building TestBalloon from the ground up: a clean, intuitive API; deep IDE integration; battle-tested robustness at scale; and first-class support for the full breadth of the Kotlin ecosystem.

### What is TestBalloon?

TestBalloon is a Kotlin Multiplatform testing framework that lets you write expressive, structured tests once and run them everywhere Kotlin runs — without compromise. It integrates seamlessly with IntelliJ IDEA, Gradle, Android Studio, and your existing toolchain.

### Highlights of the 1.0.0 release

* **Stable, production-ready API** — the API surface has been carefully refined and is now stable with binary ABI guarantees.
* **Kotlin Multiplatform** — full support for JVM, Android (instrumented & host-side), JS, Wasm/JS, Wasm/WASI, and Apple simulator targets.
* **Fixtures at every level** — test-level and suite-level fixtures, delivered as context receivers or parameters, giving each test a clean, fresh state.
* **Robolectric integration** — fast, reliable, and configurable Android testing without a device.
* **Deep IntelliJ IDEA integration** — run, debug, and jump to source directly from the test results tree; gutter icons show live test status.
* **Gradle JVM Test Suite Plugin support** — works with multi-suite Gradle projects out of the box.
* **Conditional tag-based test selection** — control test runs across all targets via environment variables.
* **Proven at scale** — validated against real-world test sets of several hundred thousand to nearly 2 million tests.
* **Extensive documentation** — guides, how-tos, migration instructions, and a blog at https://infix-de.github.io/testBalloon/.

== Thoughts

=== TestBalloon explained in one paragraph

The `testSuite` function creates a test suite. The `test` function creates a test. Suites can nest. At the top level, they are properties. You use these two functions and plain Kotlin to create any combination of  tests or suites, dynamically, with parameters, nesting, loops, whatever you need.

=== Brain

This is a brain. It can do amazing things like crypto or compiler stuff. But it doesn't want to write tests. Because writing tests can be tedious and boring and our brains don't like that.

So what can we do? Make tests easier to write. More convenient, more fun.

And I should note: Not just one kind of tests. Not just the low-hanging fruits of micro unit tests. The goal is to make all tests easy and fun to write, so that more high-value tests get written and overall quality improves.

And that's exactly what TestBalloon is trying to achieve.

[source,kotlin]
----
val NamingTests by testSuite {
    val components = listOf("Sensor", "Network", "Actor")
    val invalidNames = listOf("", "-", "a", "a space", "123")

    for (component in components) {
        testSuite("Refuse to create component '$component'") {
            for (name in invalidNames) {
                test("with name '$name'") {
                    assertEquals(Response.Failure, createComponent(component, name))
                }
            }
        }
    }
}

enum class Response { Success, Failure }
private fun createComponent(component: String, name: String) = Response.Failure
----
